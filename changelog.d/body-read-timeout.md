kind: Request body read timeout (Limits::body_read_timeout, 60 s)
---
- **New limit, every adapter (ROADMAP row 17, first slice; httpant#73):** `Limits::body_read_timeout` (default **60 s**, `Duration::ZERO` = off, off in `Limits::unlimited()`): a request body that goes that long without any data, while a handler (or the drain) waits for the next piece, fails the read with the new `httpant_core::Error::BodyTimeout` (answered `408`; `BodyReadTimeout` is the marker a body reports, as `BodyLimitExceeded` is for the size limit; `Error` is `non_exhaustive`, so the variant is additive). An idle time, like nginx's `client_body_timeout`, not a total: an upload that keeps moving is never cut. The clock runs only while somebody waits for data, so a handler that does other work before it reads is not charged. One wrapper on the service every adapter runs (`idle.rs`), so it is HTTPAnt's own limit on all six, not something inherited from the libraries.
- **Changes a default's behaviour:** a client that stalls mid-body used to hold the handler for as long as the underlying server allowed (nothing in HTTPAnt bounded it, and the libraries differ); it is now cut at 60 s. A server that takes uploads over slow links with long pauses should raise it with `Limits::body_read_timeout`.
- Conformance case 21 `body-read-timeout` with the mutant `no-body-read-timeout` (a stalled body answered `408` within the timeout on every adapter; a body arriving in pieces for four times the timeout, each piece inside it, is read whole); the mutant fails it with "was waited for past 5 s". `Setup` gains a `limits` field so a case can pick the limits it serves with. Unit tests in `idle.rs` (stall, moving body, zero, the clock runs only while somebody waits). Not in this slice: the header read timeout and the connection limit (row 17, next slices), and a `ServerSettings` key for the new limits. Not published.
