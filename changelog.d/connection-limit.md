kind: Limits::max_connections (10,000) and a per-adapter table of limits
---
- **New limit (ROADMAP row 17, second slice; httpant#73):** `Limits::max_connections` (default **10,000**, `0` = off, off in `Limits::unlimited()`). At the limit the accept loop stops accepting and clients wait in the operating system's queue until a connection closes; nothing is refused or dropped. One gate (`connections.rs`) that each accept loop passes through before it accepts; the slot rides with the connection's I/O and goes back when it is dropped. Enforced on hyper, axum, actix-web (its own `max_connections`, per worker, so the total rounds up to an even number), poem and salvo, cleartext and TLS; **not on warp**, whose accept loop is private to warp: declared `connection_limit: No` (new `Capabilities::connection_limit`) and held by the case.
- **Changes a default's behaviour:** a server that has more than 10,000 connections open at once now stops accepting past that, where before only the operating system and the library limited it. Raise it with `Limits::max_connections` (and `ulimit -n`) for a server that really holds more.
- **Open files, stated (PM condition 2026-11-12):** on Unix each connection is a file descriptor. If the soft limit is below `max_connections` + 256, HTTPAnt raises the soft limit to what it needs (never past the hard limit); if the hard limit cannot hold it, starting fails with the new `Error::ConnectionLimitTooHigh` (500; the message names the numbers and `ulimit -n`), not mid-run. New dependency on Unix only: `rlimit` 0.11 (MIT, Rust 1.65). Windows has no per-process limit to check. Tested here on Windows and on Ubuntu (WSL): `a_limit_the_process_cannot_hold_fails_at_start`.
- Conformance case 22 `connection-limit` with the mutant `no-connection-limit`: limit of four, four connections each answered and kept open, a fifth client gets no answer while they are open and is served when one closes; an adapter that declares `connection_limit: No` must serve the fifth at once. Passes on all six adapters on Windows and on Ubuntu; the mutant fails it. **Not tested:** the limit on the TLS listeners (the case is cleartext; the gate is the same code path).
- **`docs/LIMITS-BY-ADAPTER.md` (PM condition):** one table of which of the three limits HTTPAnt enforces and which it inherits, per adapter, with the measured default of each (header read: hyper, axum, poem, warp none within 40 s, salvo 30 s, actix-web 5 s). The header read timeout and idle keep-alive are the next slice. Not published.
